n2x migration engine
首页 开始 示例 概念 注意 GitHub ↗

Rust · sans-IO · 可恢复

数据迁移框架

n2x 把一次迁移拆成有顺序的步骤，并持久化每一步的进度、意图和提交凭证。 进程中断后从检查点继续；已经提交的写入不会重复执行。

开始使用 看示例
Rust 2024 不绑定异步运行时 原生 / Web
terminal 
# 启动本地 lab（JSON、SQLite、目录）
$ cargo run -p n2x-migration-lab
http://127.0.0.1:8427

# 或者直接跑四个示例测试
$ cargo test -p n2x-migration-lab --test scenarios

适合

需要断点续跑和明确提交边界的迁移

  • 跨版本、多步骤的数据升级。
  • 写入端可以做到幂等，或可以权威对账。
  • 需要暂停、恢复、重启后继续。
  • 原生与 Web 平台共用同一套调度逻辑。
不适合

一次性脚本或跨系统分布式事务

  • 失败后从头重跑也无所谓的任务。
  • 需要两阶段提交或全局锁。
  • 把 KV 当数据仓库或全量导出载体。
  • 需要后台守护进程或多写者租约。

run it first

先跑起来，再接自己的数据库。

lab 使用真实的 SQLite、JSON 和目录，不需要额外服务。

1

启动 lab

在仓库根目录执行，默认监听 127.0.0.1:8427。

cargo run -p n2x-migration-lab
2

选择 v1，逐步执行

页面会显示建表、导入 JSON、搬迁目录、清理源目录和校验。 一个版本包含多个 Step，全部完成后才推进版本。

观察 建表 → 4 条用户 → a/ 复制到 b/ → 删除 a/ → 校验
3

查看状态

页面同时显示权威版本、SQL user_version、运行状态和实际数据。

预期 version v1 sql_version 1 users 4 行 files.a false files.b 4 项
