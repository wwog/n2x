Manifest / Revision

用途：声明一条版本边，以及边内按顺序执行的步骤。

Manifest {
    id: "import-users".into(),
    from: "v0".into(),
    to: "v1".into(),
    steps: vec![
        Step {
            id: "create".into(),
            kind: StepKind::Task(call("sql.create", &["target"])),
            policy: Default::default(),
        },
        Step {
            id: "copy".into(),
            kind: StepKind::Transfer(Box::new(spec)),
            policy: Default::default(),
        },
        Step {
            id: "verify".into(),
            kind: StepKind::Check(call("users.verify", &["target"])),
            policy: Default::default(),
        },
    ],
    metadata: Default::default(),
}
字段说明
from / to版本标识。不推断数值大小，不自动生成反向边。
steps顺序固定；全部确认后才推进到 to。
RouteUnique 找唯一路径；Explicit 指定经过的边。
计划摘要运行开始时冻结；恢复时重新编译并比较，不匹配返回 PLAN_CHANGED。
设计说明：为什么版本是图而不是一个函数

数据形态可能经历多次升级，也可能存在不同路径。把所有变化写进一个函数， 恢复时无法知道“当前应该执行到哪一段”。Manifest 把路径变成数据， 每一步都有稳定 ID，可以保存进度、重开和单独校验。

Task / Transfer / Check

用途：把迁移拆成三种恢复语义不同的步骤。

类型适合做什么关键约束
Task建表、发布、清理、执行一条 SQL一次副作用；写入端必须能去重或对账
Transfer读一批、可选转换、按单位写入有界批次；游标只在整批确认后推进
Check行数、约束、索引、文件内容校验只读；失败阻止版本推进
StepKind::Task(call("sql.create_users", &["target"]))

StepKind::Transfer(Box::new(TransferSpec {
    read: stream("source", "users"),
    transform: None,             // None = 直接传递 Envelope
    write: stream("target", "users"),
    consistency: ReadConsistency::Frozen,
    read_limits: Default::default(),
    write_limits: Default::default(),
    invalid_data: Default::default(),
}))

StepKind::Check(call("users.verify", &["target"]))
设计说明：为什么 Transfer 要冻结输出

读取批次和写入单位不是一回事。转换结果必须先固定下来，恢复时不能重新生成 不同的输出；否则同一个 OperationId 可能对应不同内容。批次完成后才推进游标， 部分写入只能推进已确认前缀。

Run / Scope / Status

用途：Scope 表示长期资源，Run 表示一次迁移尝试。

RunRequest {
    run: "run-2026-11-06".into(),   // 一次尝试
    scope: "account/42".into(),     // 资源实例
    initial: Some("v0".into()),     // 首次引导时的版本
    target: "v2".into(),
    route: Route::Unique,
    policy: Default::default(),
}
状态含义下一步
Ready计划已准备开始 tick / run
Running正在执行继续 tick / run
Recovering重开后验证现场继续 tick / run
Waiting等待重试或资源按等待原因调度唤醒
Paused安全边界暂停Resume
NeedsAttention存在未知结果对账或人工确认
Completed全部确认读报告；按需回收
Failed执行停止修复后显式 Resume
Cancelled已停止后续工作不隐含回滚；可显式继续

版本权威在 ScopeState.current；只有整条边的所有步骤确认后才更新。 失败、暂停、取消不会自动撤销已完成的业务写入。

执行控制

用途：由宿主决定执行节奏。框架不启动线程，也不自己睡眠。

migrator.start(request).await?;

// 一条命令：适合调试或宿主事件循环
let _ = migrator.tick().await?;

// 连续执行：内部循环 tick，直到没有待执行命令
let report = migrator.run().await?;

// 控制信号
migrator.control(Control::Pause)?;
migrator.control(Control::Resume)?;
migrator.control(Control::Cancel)?;
API粒度
tick一条协议命令，包含持久化边界
run连续 tick 到完成、暂停、失败或待处理
snapshot最近已确认的运行视图
pending_command下一条命令，仅用于显示或单步调试
设计说明：sans-IO 的边界

核心只产出 Command、接收 Reply。数据库、文件、平台时钟 都由宿主实现。这样同一套顺序逻辑可以跑在原生、Web 和测试里，也能把一次运行 拆成命令逐条重放。

Intent / Receipt

用途：处理“目标端已经写入，但进程在拿到确认前退出”的窗口。

一次副作用按这个顺序执行：

1

持久化 Intent

请求、OperationId、request_digest 先写入工作区。

2

执行 Apply

写入端执行业务效果，并把去重凭证与业务写入放在同一个事务里。

3

保存 Receipt 与检查点

凭证、位置、计数和事件一次原子提交，然后才发下一步。

pub enum ReconcileResult {
    Applied(Receipt),
    NotApplied,
    InFlight,
    Unknown,
}

pub enum ApplyState {
    NotApplied,
    Applied(Receipt),
    Unknown,
}
结果含义处理
NotApplied权威确认没有应用，也不会有迟到提交按策略重试
Applied凭证已知接受凭证，推进检查点
Unknown可能部分或全部应用先 reconcile，不直接重放

写入端的义务：同一个 OperationId 重试时请求内容不变； 相同 ID 不同 request_digest 必须拒绝；去重凭证与业务效果原子保存； reconcile 只能返回权威结果。

设计说明：为什么不用分布式事务

业务库和工作区不在同一个事务里，跨系统的“提交确认”本来就有未知窗口。 Intent/Receipt 把这个窗口变成显式状态，而不是假设它不存在。框架保证顺序和持久化， 具体幂等实现仍由适配器负责。

Workspace / 保留

用途：保存版本、计划、恢复快照、提交凭证、事件和报告。

内容默认
版本与绑定每个 Scope 一份，覆盖写
计划 / 恢复快照 / 报告每个 Run 一份，直到回收
提交收据每个 Run 最近 128 条
事件每个 Run 1,000 条；整个工作区 20,000 条
隔离记录按 (run, step, batch) 保存，直到回收
归档retire 前写入 state/archive/*.ndjson
let report = migrator.report(run.clone()).await?;

migrator
    .retire_run("retire-1".into(), run, true)
    .await?;

一次 WorkspaceCommit 的所有变更和提交收据放在同一个 KV 帧里； Durable 还要求 flush 成功。归档先于删除，归档失败时 KV 不变。

设计说明：为什么 KV 只放状态

KV 是可恢复存储，不是数据仓库。大批次、文件内容和隔离记录要么走 Blob， 要么在回收时写入归档。提交收据和历史事件有明确上限，避免长期运行把 小 KV 撑满。完整策略见 注意事项。

事件

用途：给 UI 或消费者提供进度和关键事实；恢复仍以持久检查点为准。

类型语义
Notice临时观察事实，可合并，不作为恢复依据
StoredNotice与检查点原子保存；ID 为 RunId + sequence
EventPage::Gap请求位置早于保留历史；附当前快照
NoticeAck订阅者已处理的连续前缀；接收者需对重发去重
let page = migrator.events_after(run.clone(), last_seen, 100).await?;

migrator
    .subscribe("sub-1".into(), NoticeAck {
        subscriber: "ui".into(),
        run: run.clone(),
        through_sequence: 0,
    })
    .await?;

migrator
    .acknowledge("ack-1".into(), NoticeAck {
        subscriber: "ui".into(),
        run: run.clone(),
        through_sequence: 10,
    })
    .await?;

未确认事件不能被裁掉；容量满时提交返回背压，ACK 或回收旧运行后重试同一个 CommitId。

设计约束

这些约束决定了哪些行为由框架保证、哪些必须由适配器保证。

  • 外部副作用在 Intent 持久化之后才执行；下一条命令在凭证和检查点提交之后才发出。
  • 相同 CommitId + 相同摘要可以重放；相同 ID 不同内容拒绝。
  • 版本权威只在整条边完成后推进；失败、暂停、取消不自动回滚。
  • 单写者模型；KV 没有 CAS，也没有跨进程租约。
  • 写入端负责幂等或权威对账；框架只检查声明，不能替适配器实现。
  • KV 只保存恢复所需状态；历史有上限，回收前可写归档。
