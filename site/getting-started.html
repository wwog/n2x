getting started

从运行 lab 开始

这一页按“先看效果，再接自己的代码”的顺序组织。第一步不需要写任何适配器； 第二步开始声明迁移边；第三步实现端口并启动执行。

Rust 2024 约 15 分钟 需要 SQLite（lab 自带）

本页

1. 运行 lab 2. 加依赖 3. 声明一条边 4. 实现端口 5. 启动与执行 6. 状态与报告 7. 保留与归档 下一步

示例源码在 tests/scenarios.rs。

1. 运行 lab

lab 是一个本地网页服务，使用真实的 SQLite、JSON 和目录。它在测试项目里， 不属于框架发布内容，但用到了全部公共入口。 

cargo run -p n2x-migration-lab
# 打开 http://127.0.0.1:8427

在页面里依次操作：

操作你会看到
目标选择 v1，点击“准备逐项迁移”只编译并保存计划，版本仍是 v0
多次点击“完成下一项”建表、导入 4 条用户、复制目录、删除源目录、校验
全部步骤完成版本推进到 v1，SQL user_version = 1，a/ 已删除
预期状态 version v1 sql_version 1 users 4 行 files.a false files.b files/readme.txt, files/nested/note.txt, ...

这一步只运行，不写代码。接下来开始把同样的结构放进你自己的项目。

默认启用 engine 和 native-kv。如果平台自己实现存储，只启用 engine。

3. 声明一条边

一条 Manifest 是一个版本边。边里按顺序放 Task、 Transfer、Check。下面这条边包含建表、导入和校验： 

use n2x::{ActionCall, ActionRef, Manifest, Step, StepKind};

fn aref(id: &str) -> ActionRef {
    ActionRef { id: id.into(), revision: 1 }
}

fn call(id: &str, ports: &[&str]) -> ActionCall {
    ActionCall {
        action: aref(id),
        ports: ports.iter().map(|port| (*port).into()).collect(),
        config: None,
    }
}

fn manifest() -> Manifest {
    Manifest {
        id: "import-users".into(),
        from: "v0".into(),
        to: "v1".into(),
        steps: vec![
            Step {
                id: "create-users".into(),
                kind: StepKind::Task(call("sql.create_users", &["target"])),
                policy: Default::default(),
            },
            Step {
                id: "copy-users".into(),
                kind: StepKind::Transfer(Box::new(TransferSpec {
                    read: StreamSpec { port: "source".into(), stream: "users".into(), config: None },
                    transform: None,
                    write: StreamSpec { port: "target".into(), stream: "users".into(), config: None },
                    consistency: ReadConsistency::Frozen,
                    read_limits: Default::default(),
                    write_limits: Default::default(),
                    invalid_data: Default::default(),
                })),
                policy: Default::default(),
            },
            Step {
                id: "verify-users".into(),
                kind: StepKind::Check(call("users.verify", &["target"])),
                policy: Default::default(),
            },
        ],
        metadata: Default::default(),
    }
}

需要先导入 TransferSpec、StreamSpec、ReadConsistency。 完整 helper 见 manifest.rs。

字段说明
字段说明
from / to版本标识，不推断大小关系，也不自动生成反向边。
steps按顺序执行；全部确认后才推进到 to。
Task一次有恢复契约的副作用，例如建表、发布、清理。
Transfer读批次 → 可选转换 → 分单位写入；整批确认后才推进游标。
Check只读校验；失败阻止版本推进。
ActionRef.revision实现修订号。恢复时会校验，改行为必须增加。

4. 实现端口

端口是框架与真实资源之间的边界。按步骤类型注册对应的实现：

步骤需要的实现最小职责
TaskTaskAction执行副作用；支持去重或权威对账。
TransferReader + Writer（可选 TransformAction）有界读取、稳定游标；按单位写入并返回凭证。
CheckCheckAction只读校验；失败返回错误。

先看写入端。框架在 Apply 前持久化 Intent，重试时复用同一个 OperationId；写入端必须拒绝“同一个 ID、不同请求摘要”，并能在重开后回答“做没做”。 

use std::collections::BTreeMap;
use n2x::runtime::{PortFuture, PortResult, ResourcePort, Writer};
use n2x::*;

#[derive(Default)]
struct Target {
    // 演示用内存表；生产环境必须与业务写入放在同一个事务里。
    applied: BTreeMap<OperationId, Digest>,
}

impl ResourcePort for Target {
    fn binding(&self) -> PortBinding {
        PortBinding {
            port: "target".into(),
            resource: "sqlite/example".into(),
            adapter: ActionRef { id: "target.writer".into(), revision: 1 },
        }
    }
}

impl Writer for Target {
    fn capabilities(&self, _: &StreamSpec) -> Result<WriterCapabilities, N2xError> {
        Ok(WriterCapabilities {
            recovery: RecoveryCapabilities {
                replay: ReplaySafety::Deduplicated { retention: None },
                authoritative_lookup: true,
                durability: Durability::Durable,
            },
            limits: BatchLimits::default(),
            atomic_unit: true,
        })
    }

    fn apply(&mut self, request: ApplyRequest)
        -> PortFuture<'_, Result<Receipt, OperationFailure>>
    {
        Box::pin(async move {
            let EffectRequest::Write { items, .. } = &request.effect else {
                return Err(failure("target expects Write", ApplyState::NotApplied));
            };
            if let Some(old) = self.applied.get(&request.context.id) {
                if *old != request.context.request_digest {
                    return Err(failure("operation reused", ApplyState::NotApplied));
                }
            } else {
                // 在这里写 items。真实实现要把写入和 applied.insert 放在同一个事务。
                self.applied.insert(
                    request.context.id.clone(),
                    request.context.request_digest,
                );
            }
            Ok(Receipt {
                operation: request.context.id,
                request_digest: request.context.request_digest,
                proof: None,
            })
        })
    }

    fn reconcile(&mut self, request: ReconcileRequest)
        -> PortResult<'_, ReconcileResult>
    {
        Box::pin(async move {
            Ok(match self.applied.get(&request.request.context.id) {
                Some(digest) if *digest == request.request.context.request_digest => {
                    ReconcileResult::Applied(Receipt {
                        operation: request.request.context.id,
                        request_digest: *digest,
                        proof: None,
                    })
                }
                Some(_) => return Err(err("operation reused")),
                None => ReconcileResult::NotApplied,
            })
        })
    }
}

failure / err 是省略的错误构造函数。 真实 SQLite 适配器见 fixtures.rs。

Reader 返回什么：ReadBatch 与 SourceState

Reader 每次返回一个有界批次。首批建立 SourceState，后续批次必须与它一致； eof == false 时 next 必须存在并且能前进。 

use n2x::runtime::Reader;
use n2x::*;

#[derive(Default)]
struct Source;

impl Reader for Source {
    fn capabilities(&self, _: &StreamSpec) -> Result<ReaderCapabilities, N2xError> {
        Ok(ReaderCapabilities {
            consistency: vec![ReadConsistency::Frozen],
            resumable: true,
        })
    }

    fn read(&mut self, request: ReadRequest) -> PortResult<'_, ReadBatch> {
        Box::pin(async move {
            // 按 request.cursor / request.limits 读取；这里只演示返回结构。
            let source = SourceState {
                resource: "json/users".into(),
                consistency: ReadConsistency::Frozen,
                token: None,
            };
            Ok(ReadBatch {
                items: vec![],   // 本批 Envelope
                next: None,      // 未结束时必须是 Some(Cursor)
                eof: true,
                source,
            })
        })
    }
}
注册表与命名规则

Registry 的 map key 必须等于实现的 binding().port； ActionCall.action 必须与实现的 action() 完全一致，包括 revision。 

let mut registry = Registry::default();
registry.readers.insert("source".into(), Box::new(Source::default()));
registry.writers.insert("target".into(), Box::new(Target::default()));
registry.tasks.insert(aref("sql.create_users"), Box::new(CreateUsers));
registry.checks.insert(aref("users.verify"), Box::new(VerifyUsers));

5. 启动与执行

原生入口会先取得独占锁，再打开 state.kv 和 archive/。 start 编译或恢复计划；run 连续执行；tick 只执行一条命令。 

use n2x::{Migrator, Route, RunRequest};

let mut migrator = Migrator::open_native("./state", vec![manifest()], registry)?;

let run: RunId = "run-2026-11-06".into();
migrator
    .start(RunRequest {
        run: run.clone(),
        scope: "account/42".into(),
        initial: Some("v0".into()),
        target: "v1".into(),
        route: Route::Unique,
        policy: Default::default(),
    })
    .await?;

// 连续执行到没有待执行命令，然后返回已保存的报告。
let report = migrator.run().await?;
println!("{:?}", report.outcome);

这里的 .await 需要由你的执行器驱动。n2x 不绑定 Tokio； 仓库测试使用 futures::executor::block_on。

i run 与 tick： tick 推进一条协议命令，适合调试和宿主事件循环； run 循环调用 tick，遇到失败或需要人工处理时返回错误。
暂停、恢复、取消 
migrator.control(Control::Pause)?;   // 下一个安全边界暂停
migrator.control(Control::Resume)?;  // 继续
migrator.control(Control::Cancel)?;  // 停止后续工作，不自动回滚

暂停、恢复、取消都是控制信号；它们不会撤销已经完成的外部写入。 失败或待处理的运行需要先处理，再恢复。

6. 状态与报告

三个查询入口：snapshot() 看当前运行，report(run) 读已保存报告，events_after(run, after, limit) 补读关键事件。 

if let Some(snapshot) = migrator.snapshot() {
    println!("{:?} {:?} -> {:?}", snapshot.status, snapshot.current, snapshot.target);
}

let stored = migrator.report(run.clone()).await?;
let page = migrator.events_after(run, 0, 100).await?;
状态含义 / 下一步
Completed全部步骤和版本推进已确认；读取报告，按需回收。
Failed执行停止；修复后显式 Resume，不会自动回滚。
NeedsAttention存在未知结果；先对账或人工确认，不能直接重试。
Paused已在安全边界暂停；Resume 继续。
Running / Recovering继续 tick / run。

7. 保留与归档

已完成运行会保留计划、恢复快照、报告、事件和隔离记录。读取报告后， 用 retire_run 回收。原生组合会先把这些材料写入 state/archive/<run>-<hash>.ndjson，成功后才删除 KV。 

let report = migrator.report(run.clone()).await?.expect("report");
// 导出 report / 隔离记录 ...

migrator
    .unsubscribe("unsub-1".into(), run.clone(), "ui".into())
    .await?;

// true = 保留报告作为 RunId 墓碑；false = 报告也删，归档里仍有。
migrator
    .retire_run("retire-1".into(), run, true)
    .await?;

活动、暂停、失败、取消或仍有可靠订阅者的运行不会被回收。 容量与归档格式见 注意事项。
